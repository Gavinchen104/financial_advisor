## P2-C — what landed
- `src/rag/edgar.py`: `EdgarClient` — ticker → CIK via `company_tickers.json` (mirrored on disk, used when SEC is down), `list_filings()` (latest 1 10-K + 2 10-Qs by default; exact form match so 10-K/A is skipped), primary-document download cached under `data/raw/edgar/{cik}/{accession}.html`, ≤ 5 req/s across threads, tenacity backoff on 429/5xx, no retry on 404. `supplemental_documents()` pulls large sibling `.htm` files (Exhibit 13, a second main `.htm`) for wrapper-style primaries (Wells Fargo, IBM), skipping XBRL viewer pages and boilerplate exhibits.
- `src/rag/html_text.py`: lxml-based iXBRL cleanup (ix:header / display:none dropped before extraction, no `ix:` / `us-gaap:` residue), tables → one row per line with `$` / `)` / `%` cell merging and spacer cells dropped, inline spans kept inline, NFKC + dash/quote normalization. Section splitter with three strategies in order: Item-labelled headings (longest-span occurrence wins, which skips the TOC and a 10-Q's Part II), title-only headings (Morgan Stanley / McDonald's / GE / bank "cross-reference index" filings), else `full`. A split must cover ≥ 30% of a 10-K / ≥ 15% of a 10-Q (cross-reference stubs produced 0–13% "sections"), and a pointer-only Item 8 ("see page 58": Disney, PepsiCo, Chevron, Oracle) is rescued from the statements printed after Part IV. `SectionSplit` reports `mode`, `coverage`, `missing_required`.
- `src/rag/chunk.py`: ~450-token chunks (chars/4) with 15% overlap, section-bounded, table rows never split, long paragraphs split into sentences and re-joined, every chunk prefixed with `"{company} {form} {period} — {section title}"`; a single unit above 7,000 chars is hard-split so nothing exceeds the 2,048-token embedding limit.
- `src/rag/embed.py`: `embed_documents()` / `embed_query()` on `gemini-embedding-001`, 768-d, task types RETRIEVAL_DOCUMENT / RETRIEVAL_QUERY, L2-normalized, batches of 50, retries on 408/429/5xx, texts over the model limit truncated with a warning, `llm.Budget` reused so `--max-usd` refuses the batch that would cross the cap. Token counts are estimated as chars/4 (the Developer API returns no usage for embeddings).
- `src/rag/ingest.py`: `ingest_filing()` (skip if the accession is in `filing_docs`, fetch, thin-primary sibling lookup, prepare, embed, store in one caller-owned transaction), `run_ingestion()` (per-filing transactions, stops at `BudgetExceeded`), `store_filing()` (minimal company node if the ticker is outside the seeded graph, `filing:` node with form/period/url/sections props, `filed` edge, `filing_docs`, `filing_chunks` with halfvec literals), `load_universe()`, `summarize()` / `write_summary()` → `results/ingest_summary.md`.
- `scripts/ingest_filings.py --tickers | --universe [--dry-run] [--max-usd] [--forms] [--refetch] [--replace] [--corpus]`; `data/universe.txt` (50 largest S&P 500 names, hand-maintained, gitignore exception); `.github/workflows/refresh-filings.yml` (weekly, exits green until `DATABASE_URL` / `GEMINI_API_KEY` secrets exist).
- Tests: `test_edgar.py` (respx: CIK cache + mirror fallback, exact-form selection, caching, 429/503 retries, 404 no retry, throttle, sibling-document selection), `test_html_text.py` (3 HTML fixtures incl. a tricky TOC + inline title-only / pointer-Item-8 / cross-reference-stub documents, cell merging, normalization, coverage fallback), `test_chunk.py`, `test_embed.py` (fake client: batching, task types, unit norm, retries, budget, truncation), `test_ingest.py` (dry run, sibling pull-in, SQL issued by `store_filing`, budget stop, universe file, summary), `test_ingest_pg.py` (5 `@pg`: doc + chunks + tsvector + graph links, skip/replace, dry run writes nothing, seeded node kept, vector search finds the planted chunk). 225 SQLite tests, 21 pg tests.

## Decisions
- 2026-10-28: The Postgres-only RAG tables (`kg_*`, `filing_*`) are raw DDL in the migration, not ORM models; `env.py` excludes them from autogenerate. Only `ask_log` is an ORM model because it must exist on SQLite too — keeps the SQLite suite and `alembic check` clean.
- 2026-10-28: pg tests read `PG_TEST_URL` (conftest forces `DATABASE_URL` to SQLite before importing `src`). When it is set but the DB is unreachable the tests fail rather than skip, so CI cannot go green without the pgvector service.
- 2026-10-28: `llm.Budget.reserve()` guards with a worst-case local estimate (chars/4 input + full `max_tokens` output), so no call can cross `--max-usd`; `llm.estimate()` (`count_tokens`) is the exact number for `--dry-run`.
- 2026-10-28: `config.price_for()` falls back to the longest prefix match so dated snapshot ids echoed by the API (`claude-haiku-5-5-2026…`) still price; unknown models raise instead of guessing.
- 2026-10-28: Deploy caveat — `init_db()` applies this migration at boot, so a production Postgres must have pgvector ≥ 0.7 or the app will not start (a SQLite deployment is unaffected). Verify on Render (`SELECT extversion FROM pg_extension WHERE extname = 'vector';`) before merging `feat/rag` into `main`.
- 2026-10-28: The Claude Code sandbox cannot reach Docker or `localhost:5432`, so Postgres-backed tests are run by Gavin (`!` prefix) or by CI. `ci.yml` therefore also runs on pushes to `feat/**`, so the branch gets the pgvector job without opening a PR.
- 2026-10-28: Local dev venv is Python 3.11 (Homebrew). Homebrew postgresql@16 has no pgvector and collides with the compose port — keep it stopped (`brew services stop postgresql@16`) while working on RAG.
- 2026-10-28 (P2-B): Follow-up migration `c4d1e8a2f906` instead of hacks. §4 has no column for macro-edge direction/override (needed by `get_macro_sensitivity` and the UI), and `UNIQUE (src, dst, type, source, accession)` never conflicts for curated/gics edges (NULL accession), so `ON CONFLICT` upserts could not be idempotent. Added `kg_edges.props JSONB` + a partial unique index on `(src, dst, type, source) WHERE accession IS NULL`. Revert = `alembic downgrade 7b3e9d2c4a1f` plus dropping the two uses in `kg_store.py`. Flagged for Gavin's sign-off per CLAUDE.md ("ask before changing the DB schema").
- 2026-10-28 (P2-B): Curated rationale is stored in `kg_edges.evidence` (the plan asks `/context` to expose `evidence` per edge); filing edges will store the verbatim quote there. `source` ∈ {`curated`, `gics`, `filing`}; macro edges are `curated` (both sector defaults and overrides are hand-authored).
- 2026-10-28 (P2-B): `major_customer` (5 JSON edges, previously ignored by every query) is read as reversed `supplies_to` in both backends. The JSON file is untouched; the mapping lives in `canonical_edges()`.
- 2026-10-28 (P2-B): Both backends keep a curated and a GICS edge for the same pair as separate edges (that is the provenance), and the query API dedupes per counterparty, heavier edge first. The DB graph is loaded `ORDER BY id` (= JSON order at seed time) so tie-breaking matches the JSON graph exactly; `get_sector_peers` sorts by ticker for the same reason.
- 2026-10-28 (P2-B): The compose `stockify` DB is both the dev DB and the local pg test DB, so every pg test must be hermetic: `test_kg_store_pg.py` deletes `kg_*` rows inside its rolled-back transaction before seeding. Seeding the whole graph in a test takes well under a second.
- 2026-10-28 (P2-B): Nodes are never deleted by the seed (filing edges/facts cascade from them); companies that leave the S&P 500 stay as nodes. Production seeding (Neon/Supabase) stays a P2-J step; `refresh-knowledge-graph.yml` only rebuilds the JSON.
- 2026-10-31 (P2-C): Embedding token counts are chars/4 estimates everywhere (dry run, budget, summary): the Gemini Developer API returns no usage for `embed_content`. The estimate is conservative for English prose; the spend log records estimates, not invoices.
